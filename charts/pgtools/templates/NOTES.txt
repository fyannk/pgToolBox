{{- if .Values.console.enabled }}
The console {{ .Chart.AppVersion }} is installed in namespace {{ .Release.Namespace }}, watching: {{ include "pgtools.console.watchNamespaces" . | fromJsonArray | join ", " }}.

It asks the API server about every request with a SelfSubjectAccessReview sent
with the signed-in user's own token, so people see only what Kubernetes RBAC lets
them see in those namespaces. Grant a person or group access with an ordinary
RoleBinding, for example read access to the Clusters of a watched namespace:

  kubectl -n {{ index (include "pgtools.console.watchNamespaces" . | fromJsonArray) 0 }} create role cluster-viewer \
    --verb=get,list,watch --resource=clusters.postgresql.cnpg.io
  kubectl -n {{ index (include "pgtools.console.watchNamespaces" . | fromJsonArray) 0 }} create rolebinding cluster-viewer --role=cluster-viewer --group=<group>

{{- if .Values.console.instanceStatus.caBundleConfigMap }}

The console verifies each instance's /pg/status against a CA bundle YOU supply.
Until the ConfigMap exists every Cluster reads "not verifiable". Create it from
the Clusters' server CAs (only ca.crt; never ca.key):

  for c in $(kubectl -n <ns> get clusters.postgresql.cnpg.io -o name | cut -d/ -f2); do
    kubectl -n <ns> get secret "$c-ca" -o jsonpath='{.data.ca\.crt}' | base64 -d
  done > ca.crt
  kubectl -n {{ .Release.Namespace }} create configmap {{ .Values.console.instanceStatus.caBundleConfigMap }} --from-file=ca.crt=ca.crt

CloudNativePG renews its self-signed CAs every 90 days: a copy made once expires.
Keep the bundle current (trust-manager, or one long-lived serverCASecret; see
the chart README, "The /pg/status CA bundle").
{{- end }}

pgAdmin {{ .Values.pgadmin.image.tag }} is installed in namespace {{ .Release.Namespace }}, without the operator,
with {{ len .Values.pgadmin.servers }} declared server(s). Sign-in: {{ .Values.pgadmin.auth.provider }} only (no local password).

What this gives up next to the operator's PgAdmin:
  - a new Cluster or DatabaseRole is not registered until you add it to
    pgadmin.servers and run `helm upgrade`;
  - which Secret holds which credential is named by you; the sidecar checks it
    against the live Cluster or DatabaseRole and refuses a mismatch;
  - Clusters of other namespaces cannot be offered;
  - no status in the console: why a server has no password is in the sidecar's log:

  kubectl -n {{ .Release.Namespace }} logs deploy/{{ $pga }} -c passfile-sync

below{{ end }} (Role {{ $pga }}-credentials, get and watch by name).
{{- if $derived }}
{{- $example := index $derived 0 }}

DEPRECATED: a server without caSecret or caConfigMap gets its CA from <cluster>-ca, a Secret
pgadmin.servers does not name. The Role grants get and watch on:
{{- range $derived }}
  - {{ . }}
{{- end }}
CloudNativePG's own <cluster>-ca Secret also holds ca.key, the CA's signing key: the sidecar
copies only ca.crt, but the Role lets the Pod read the key. The next minor release requires
caSecret or caConfigMap on every server. Prefer caConfigMap, a ConfigMap holding only ca.crt:
the Role then names no CA Secret for those servers. For {{ $example }}:

  kubectl -n {{ .Release.Namespace }} get secret {{ $example }} -o jsonpath='{.data.ca\.crt}' | base64 -d > ca.crt
  kubectl -n {{ .Release.Namespace }} create configmap {{ $example }}-crt --from-file=ca.crt=ca.crt

and set caConfigMap: {{ $example }}-crt on every server of Cluster {{ trimSuffix "-ca" $example }}.
CloudNativePG renews its self-signed CAs (every 90 days by default): keep the copy current
(trust-manager, or one long-lived serverCASecret).
{{- end }}
